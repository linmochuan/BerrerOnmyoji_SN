# lin RPA

`lin RPA` は、Pythonで開発したWindows向けのデスクトップ自動化ツールです。

もともとは、繰り返し発生するデスクトップ操作を自動化することを目的として開発を始め、開発を進める中で、**画面認識、YOLOv5による物体検出、PyAutoGUIによるマウス・キーボード操作、Excelによるタスク定義、バックグラウンド処理、安全な停止制御**などの機能を実装しました。

現在の主な実行方式は、

> **Excelで操作手順を定義 → Pythonでタスクを読み込む → 画面を認識 → マウス・キーボード操作を実行**

という構成です。

また、開発初期に作成したYOLOv5によるリアルタイム画面認識および、認識結果を利用した自動操作の実験コードもリポジトリに残しています。

## 主な特徴

* **自作データセットを使用してYOLOv5モデルを学習**
* Pythonによるリアルタイム画面認識
* PyAutoGUIによるマウス・キーボード操作
* スクリーンショットを利用したテンプレート画像検索
* Excelによるデスクトップ自動化フローの定義
* Pythonコードを変更せずにExcelから操作手順を変更可能
* 通常の画像検索および継続的なグローバル画像検索に対応
* バックグラウンドスレッドによるタスク実行
* `threading.Event` を利用した安全な停止制御
* JSON / YAMLによる設定管理
* PyInstallerによるWindowsアプリケーションへのパッケージ化

# 2. 全体の処理フロー

現在のRPAメインプログラムは、`lin_RPA.py` の `main()` から起動します。

```text
lin_RPA.py 起動
      │
      ├── settings.json / YAMLを読み込む
      │
      ├── Tkinter GUIを作成
      │
      └── ユーザーの操作を待機
                │
                ▼
          Excelタスクを開始
                │
                ├── Excelを読み込む
                │
                ├── テンプレート画像を検索
                │
                ├── 検索結果を確認
                │
                ├── 操作コマンドを解析
                │
                ├── PyAutoGUIで操作
                │
                └── 次のタスクへ
```

自動化処理はバックグラウンドスレッドで実行し、TkinterのメインスレッドはGUI操作やログ表示を担当します。

そのため、画像検索や自動操作の待機中でも、メイン画面が処理によってブロックされないようにしています。

# 3. Excelによるタスク管理

自動化処理の手順をPythonコードに直接記述するのではなく、Excelファイルから設定できるようにしています。

Excelの1行を1つのタスクとして扱います。

| 列 | 項目       | 説明                  |
| - | -------- | ------------------- |
| A | 画像パス     | 検索するテンプレート画像        |
| B | 操作コマンド   | 画像発見後に実行する操作        |
| C | 検索時間     | 画像を検索する時間（秒）        |
| D | タイムアウト処理 | `skip` または指定行へのジャンプ |

例：

| 画像パス                     | 操作コマンド                 |      検索時間 | タイムアウト処理 |
| ------------------------ | ---------------------- | --------: | -------- |
| `data/images/start.png`  | `待機=0.5，左クリック=1`       |        10 | `skip`   |
| `data/images/button.png` | `オフセット=10/5，二級左クリック=2` |         8 | `2`      |
| `data/images/notice.png` | `左クリック=1`              | `グローバル検索` |          |

この方式により、操作フローを変更する際にPythonプログラム自体を変更する必要がありません。

```text
Excel
  │
  │ 操作フローを定義
  ▼
Python
  │
  │ 読み込み・解析
  ▼
タスク実行
  │
  ├── 画像検索
  ├── 条件判定
  └── PyAutoGUI
```

# 4. Excelタスクの実行

プログラムはExcelの2行目からタスクを読み込み、基本的に上から順番に処理します。

通常のタスクでは、指定された画像を画面から検索します。

```text
テンプレート画像を検索
        │
        ▼
     見つかった？
      /       \
    Yes        No
     │          │
     ▼          ▼
操作を実行    タイムアウト
     │          │
     ▼          ▼
次の行へ      skip / 指定行へ
```

最後の行まで処理した場合は、再び2行目から処理を開始します。

そのため、繰り返し実行する必要があるデスクトップ操作にも利用できます。

---

# 5. グローバル画像検索

ExcelのC列に、

```text
グローバル検索
```

と設定した場合、その画像をプログラムの実行中に継続的に検索します。

複数のグローバル検索タスクにも対応しています。

同じ画像が画面上に表示され続けている場合に何度も操作してしまわないよう、画像の状態を管理しています。

```text
画像が出現
   ↓
1回実行
   ↓
画像が表示され続ける
   ↓
再実行しない
   ↓
画像が消える
   ↓
再び出現
   ↓
再度実行
```

# 6. 操作コマンド

現在、以下の操作をExcelから指定できます。

| コマンド         | 例                         | 内容                 |
| ------------ | ------------------------- | ------------------ |
| 待機           | `待機=1.5`                  | 指定時間待機             |
| オフセット        | `オフセット=10/5`              | 座標をX+10、Y+5移動      |
| 左クリック        | `左クリック=2`                 | 指定位置を2回クリック        |
| ランダムクリック     | `二級左クリック=3`               | 対象領域内のランダムな位置をクリック |
| オフセットクリック    | `三級左クリック=10/20/1`         | 指定した位置をクリック        |
| 左ボタン押下       | `左ボタン押下`                  | 左ボタンを押す            |
| 左ボタン解放       | `左ボタン解放`                  | 左ボタンを離す            |
| 右ボタン押下       | `右ボタン押下`                  | 右ボタンを押す            |
| 右ボタン解放       | `右ボタン解放`                  | 右ボタンを離す            |
| 全画面スクリーンショット | `画面スクリーンショット`             | 現在の画面を保存           |
| 範囲スクリーンショット  | `範囲スクリーンショット=0/0/800/600` | 指定範囲を保存            |

複数のコマンドを指定することもできます。

```text
オフセット=15/8，待機=0.5，左ボタン押下，待機=1，左ボタン解放
```

上記の場合、

1. 座標を移動
2. 0.5秒待機
3. 左ボタンを押す
4. 1秒待機
5. 左ボタンを離す

という順番で処理されます。

# 7. 画面認識

RPAのメイン処理では、PyAutoGUIの画面画像検索機能を利用しています。

```python
pyautogui.locateOnScreen()
```

基本的な処理は以下の通りです。

```text
画面
 ↓
テンプレート画像を検索
 ↓
一致領域を取得
 ↓
中心座標を計算
 ↓
マウス・キーボード操作
```

以下の機能に対応しています。

* 通常のテンプレート画像検索
* 継続的なグローバル検索
* 複数画像の監視
* 検索タイムアウト
* 検索信頼度の設定
* 相対パス / 絶対パス
* スクリーンショット保存

# 8. YOLOv5による物体検出

本プロジェクトでは、テンプレート画像による画面認識とは別に、YOLOv5を利用した物体検出も実装・検証しました。

## モデル学習

実際の画面からデータセットを作成し、**自作データセットを使用してYOLOv5モデルを学習**しました。

学習したモデルの重みは、

```text
best.pt
```

として保存しています。

学習から推論までの流れ：

```text
データ収集
   ↓
アノテーション
   ↓
学習データ / 検証データの準備
   ↓
YOLOv5による学習
   ↓
モデル検証
   ↓
best.pt
   ↓
Pythonから推論
```

> YOLOv5本体のコードはオープンソースプロジェクトをベースにしています。本プロジェクトでは、主にデータセットの作成、モデルの学習、学習済みモデルの利用、およびPythonによる上位アプリケーション部分を実装しています。

# 12. 非同期処理と安全な停止

GUIが自動化処理によって停止しないよう、Excelタスクはバックグラウンドスレッドで実行しています。

```text
Tkinter メインスレッド
│
├── GUI
├── ボタン
├── ログ
│
└── start_async()
       │
       ▼
  ExcelExecutor
       │
       └── バックグラウンドスレッド
```

スレッド制御には、

```python
threading.Thread
threading.Event
```

を使用しています。

## StopController

停止状態は `threading.Event` を利用して管理します。

以下の操作で同じ停止処理を利用します。

* GUIの停止ボタン
* ウィンドウの閉じる操作
* グローバルショートカット

停止信号を受け取ると、

```text
StopController
      ↓
threading.Event.set()
      ↓
タスクループが停止状態を確認
      ↓
バックグラウンドスレッドが自然終了
```

という流れで処理を終了します。

プロセスを強制終了する方式ではなく、実行中の処理が停止状態を確認して終了する方式を採用しています。

* Excelファイル
* ワークシート
* 画像パス
* 信頼度
* 実行時間
* 設定ファイル

# 16. インストール

Pythonの仮想環境を使用することを推奨します。

```bash
python -m venv .venv
```

Windowsの場合：

```bash
.venv\Scripts\activate
```

依存ライブラリをインストールします。

```bash
pip install -r requirements.txt
```

環境によって必要な場合は、以下を追加でインストールしてください。

```bash
pip install torch opencv-python mss pyautogui pynput openpyxl PyYAML numpy
```

# 21. 補足

本プロジェクトは、個人でデスクトップ自動化およびコンピュータビジョンを学習・検証する目的で開発したものです。

YOLOv5関連部分はオープンソースのYOLOv5プロジェクトをベースとしており、本リポジトリでは主に、**自作データセットの作成、モデル学習、学習済みモデルの利用、およびPythonによる上位アプリケーション部分**を実装しています。

リポジトリ内には開発過程で作成した実験用・旧版スクリプトも含まれており、すべてのスクリプトが現在の `lin_RPA.py` の実行フローで使用されるわけではありません。

現在のRPAプログラムを実行する場合は、

```bash
python lin_RPA.py
```

を使用してください。
